# Station Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the approved Dispatch interface as a useful native terminal hub with real local data, project-scoped launchers, and durable background tasks.

**Architecture:** One Rust binary owns a Ratatui event loop, typed provider snapshots, an action runner, and a private task-supervisor entry point. Providers and filesystem work run outside the UI thread. Supervisors outlive the UI and publish task outcomes atomically.

**Tech Stack:** Rust 2024; Ratatui 0.30.2; Crossterm 0.29.0; serde/serde_json; TOML; clap; anyhow; nix 0.31.3 for Unix facilities; UUID run IDs; standard-library worker threads and bounded channels. Dev dependencies: tempfile and insta. Resolve compatible supporting dependency versions during Task 1 and commit Cargo.lock. The available compiler is Rust 1.98.1.

**Spec:** [Approved design](../specs/2026-10-03-station-design.md). Visual reference: `/home/kekn521/station-design/dispatch-v2.html`.

## Review Focus

- Unicode, non-UTF-8 filenames, spaces, and leading dashes must neither break alignment nor become command options; test in Tasks 2 and 3.
- A provider finishing after project selection changes must not overwrite the new project's state; test in Task 4.
- Huge/binary logs and terminal escape sequences must not exhaust memory or inject terminal controls; test in Tasks 4 and 7.
- Restart, concurrent Station instances, reboot, and PID reuse must preserve task outcomes without stopping unrelated processes; test in Tasks 6 and 7.
- A missing executable, foreground interruption, or UI error must restore the terminal and leave normal typing usable; test in Tasks 3 and 9.

## Shared contracts

Define types in the task that first produces them; later tasks import rather than duplicate them. Use `anyhow::Result<T>` at I/O boundaries, `PathBuf`/`OsString` for OS arguments, and stable IDs for selection.

- Task 1 defines `Section` (the nine navigation variants), `Pane`, `LayoutMode::{Wide,Compact,Single,TooSmall}`, `Availability::{Loading,Ready,Unavailable(String),Failed(String)}`, and `Snapshot<T> { value: Option<T>, availability: Availability, observed_at: Option<SystemTime>, generation: u64 }` in `model.rs`.
- Task 1 defines `Config { project_roots, pinned_projects, editor, tools, tasks, tunnels, theme }`; `ToolCommand { program: OsString, args: Vec<OsString> }`; `TaskRecipe { id: String, label: String, command: ToolCommand, cwd: PathBuf, required_ports: Vec<u16> }`; `TunnelRecipe { id: String, host: String, bind: String, local_port: u16, remote_host: String, remote_port: u16 }`. Use custom serde conversion from config strings for OS arguments.
- `App` owns config, current section/pane, stable selected IDs, search query, per-provider snapshots, and transient overlays. It exposes `App::new(Config, AppState) -> Self` and `App::update(Action) -> Vec<Effect>`; producers extend typed `Action`/`Effect` variants in their own tasks. No stringly typed dispatch.
- Task 1 defines `HitRegion { area: Rect, action: Action }`. Rendering returns hit regions; the event loop saves the completed frame's regions on App for subsequent mouse input.
- `AppState { schema_version: u32, selected_workspace: Option<PathBuf>, recent_workspaces: Vec<PathBuf>, activity: Vec<ActivityEntry> }`. `ActivityEntry { id: String, at: SystemTime, workspace: Option<PathBuf>, kind: ActivityKind, outcome: String }`; Task 1 starts with launch outcomes, Task 7 adds task-run links. IDs deduplicate concurrent updates.
